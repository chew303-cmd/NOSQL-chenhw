# task2 MongoDB 原子扣减与事务验证

## 个人参数
S=2，A=2，C=2 → **Stock = 5+C = 7**，**Buy = 1+A = 3**，`bookId = BOOK-12408060102`

## 文件
| 文件 | 作用 |
| --- | --- |
| `init_db.py` | 初始化：写入库存文档（stock=7），清空 orders |
| `task2.py` | 业务操作：原子扣减 / 结果判断 / 事务 / 四个场景测试 / 结果解释 |

## 运行
```bash
python init_db.py
python task2.py
```

## 要点
1. **原子扣减**：`find_one_and_update({"_id": BOOK_ID, "stock": {"$gte": BUY}}, {"$inc": {"stock": -BUY}})`，条件检查与扣减合成一次单文档原子写，不存在“先查再扣”的竞态。
2. **结果判断**：只看数据库返回——返回文档=成功（OK）；返回 `None`=库存不足或教材不存在（NO_STOCK）；抛 `PyMongoError`=执行异常（DB_ERROR）。
3. **事务**：`order(requestId, forceError)` 内 `start_session()` + `start_transaction()`，扣减与订单插入同一事务；扣减失败抛异常不建单；`forceError=true` 在扣减后、插入前抛异常；异常回滚、仅提交成功才返回 True。
4. **四场景**（每场景单独重置 inventory 与 orders，预期值由程序计算）：

| 场景 | 初始库存 | 购买量 | 成功 | 失败 | 最终库存 | 订单数 | 核验 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T1 正常订购 | 7 | 3 | 1 | 0 | 4 | 1 | PASS |
| T2 库存不足 | 2 | 3 | 0 | 1 | 2 | 0 | PASS |
| T3 中途异常 | 7 | 3 | 0 | 1 | 7 | 0 | PASS |
| T4 连续购买 | 7 | 3 | 2 | 1 | 1 | 2 | PASS |
